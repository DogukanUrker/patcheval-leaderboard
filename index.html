How it works

Real bugs, recent fixes

Every task is a real issue-linked bug fix from a Python repo, committed in the 8 months before the release was frozen. Most models never saw the fix in training.

Not the famous repos

No Django, no FastAPI. Those are all over the internet and in every training set. The tasks come from real, used projects that aren't that famous.

An agent, not a chat

The model works inside the Pi agent: it reads files, runs commands and edits code. No internet, no git history, no hidden tests, no gold patch in the sandbox.

Hidden tests decide

A fix counts only if the hidden fail-to-pass test passes and the existing suite stays green. A failed first try gets one repair attempt with generic feedback only.

Checked 4 ways

Before freezing, each task was proven: the test fails before the fix, passes after it, and nothing else breaks either way.

Frozen and checksummed

The 20 tasks never change. If a hidden test turns out to be unfair, it gets fixed in a numbered revision, and every past run is regraded on the patch it actually wrote. Scores from August and scores from today stay comparable.

Run it yourself

PatchEval runs through BenchKit. It builds every task's runtime locally and cleans up afterwards. Why only 20 tasks? Running SWE-bench locally is way too expensive for one GPU.

# get BenchKit
git clone https://github.com/DogukanUrker/BenchKit && cd BenchKit

# download the frozen PatchEval release
uv run benchkit datasets install patcheval

# run it
uv run benchkit --headless --models MODEL --benchmarks patcheval \
  --harness pi --repair-attempts 1
